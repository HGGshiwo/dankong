# Dankong 机器人控制与仿真环境配置指南

本指南旨在引导开发者（人或 AI Agent）从零开始顺利配置 **Dankong** 及其仿真环境（包括无人机、四足狗、无人车仿真环境）。

---

## 1. 基础系统与工具链要求

配置前请确保系统满足以下基本软硬件要求：
* **操作系统**：Ubuntu 20.04 LTS (Focal Fossa)
* **ROS 1 版本**：ROS Noetic (`ros-noetic-desktop-full`)
  * 安装指南请参考：[ROS Noetic installation](http://wiki.ros.org/noetic/Installation/Ubuntu)
* **仿真器**：Gazebo 11 (已随 `desktop-full` 自动安装)
* **核心构建工具与依赖包**：
  ```bash
  sudo apt-get update
  sudo apt-get install -y git build-essential cmake python3-pip python3-catkin-tools ros-noetic-cv-bridge libgazebo11-dev libopencv-dev libboost-all-dev libgeographic-dev geographiclib-tools
  ```

## 2. 安装 ArduPilot SITL 仿真环境

### 2.1 克隆并切换分支
克隆 ArduPilot 仓库并切换至稳定的 `Copter-4.5` 分支（若 master 分支无法编译，推荐此分支）：
```bash
# 确认安装路径（以 ~/ardupilot 为例）
cd ~
git clone https://github.com/ArduPilot/ardupilot.git
cd ardupilot
git checkout Copter-4.5
git submodule update --init --recursive
```

### 2.2 安装编译依赖
运行 ArduPilot 官方依赖配置脚本。

```bash
# 运行配置脚本
Tools/environment_install/install-prereqs-ubuntu.sh -y
```

### 2.3 配置环境变量
为了使仿真工具链（如 `sim_vehicle.py`）在任意路径下可用，将 autotest 路径加入 `~/.bashrc`：
```bash
# 写入环境变量 (请替换为实际克隆路径)
echo "export PATH=\$PATH:\$HOME/ardupilot/Tools/autotest" >> ~/.bashrc
source ~/.profile
```

### 2.4 初始化测试
验证 ArduPilot SITL 是否安装成功：
```bash
cd ~/ardupilot/ArduCopter
sim_vehicle.py -w
```
当控制台成功启动且能够输入命令时，代表 SITL 基础环境配置成功，可使用 `Ctrl+C` 退出。

## 3. 工作空间配置与源码获取

### 3.1 初始化 ROS 工作空间
```bash
mkdir -p ~/catkin_ws/src
cd ~/catkin_ws
catkin init
```

### 3.2 克隆核心仿真与控制仓库
进入工作空间的 `src` 目录，克隆所需的全部仓库：
```bash
cd ~/catkin_ws/src

# 1. 克隆 Gazebo 仿真配置包
git clone https://github.com/HGGshiwo/gazebo_sim.git

# 2. 克隆 Gazebo-ArduPilot 桥接插件
git clone https://github.com/HGGshiwo/ardupilot_gazebo.git

# 3. 克隆 Dankong 系统主程序，并克隆嵌套的 dk 框架仓库
git clone https://github.com/HGGshiwo/dankong.git
cd dankong
# 必须手动将 dk 框架克隆到 dankong 目录下（替换或填充空 dk 文件夹）
git clone https://github.com/HGGshiwo/dk.git
cd ~/catkin_ws/src
```

### 3.3 四足狗仿真包说明与依赖补全
四足狗仿真所需的包位于 `src/go1`，在空白环境中需要手动克隆这些核心仓库：
```bash
mkdir -p ~/catkin_ws/src/go1
cd ~/catkin_ws/src/go1

# 1. 克隆 CHAMP 运动学控制库
git clone https://github.com/chvmp/champ.git

# 2. 克隆 Go1 仿真配置包
git clone https://github.com/HGGshiwo/go1_config.git

# 3. 克隆 Unitree ROS 桥接与控制器
git clone https://github.com/HGGshiwo/unitree_ros.git

# 4. 克隆速度平滑器
git clone https://github.com/chvmp/yocs_velocity_smoother.git

# ================= 重要：手动补充缺失的依赖仓库 =================
# 5. 克隆 unitree_ros_to_real（编译 unitree_ros 必须的 unitree_legged_msgs 依赖）
git clone https://github.com/unitreerobotics/unitree_ros_to_real.git

# 6. 克隆 champ_teleop（键盘/手柄控制及仿真测试必需）
git clone https://github.com/chvmp/champ_teleop.git
```

## 4. 依赖项补充与 MAVSDK 安装

在编译前，必须确保所有第三方系统库和 ROS 依赖项安装完毕。

### 4.1 安装 MAVSDK
`dankong` 强依赖 MAVSDK 库。由于需要适配完全空白的多开发者环境，请直接从官方 GitHub Release 下载对应操作系统版本的预编译 `.deb` 包进行安装：

```bash
# 1. 下载对应系统版本的 pre-built deb 包（以 Ubuntu 20.04 的 v1.4.16 为例，请根据实际系统与版本要求替换）
wget https://github.com/mavlink/MAVSDK/releases/download/v1.4.16/libmavsdk-dev_1.4.16_ubuntu20.04_amd64.deb

# 2. 安装 deb 包
sudo dpkg -i libmavsdk-dev_1.4.16_ubuntu20.04_amd64.deb

# 3. 补全可能缺失的底层依赖项
sudo apt-get install -f
```

### 4.2 使用 rosdep 补全工作空间依赖 (主要针对狗仿真 `go1`)
狗仿真中使用的 `champ` 驱动与导航栈有大量 ROS 依赖，使用 `rosdep` 可一键补全：
```bash
# 初始化并更新 rosdep (若已配置可跳过前两步)
sudo rosdep init
rosdep update

# 执行依赖检测与安装
cd ~/catkin_ws
rosdep install --from-paths src --ignore-src -r -y
```

## 5. 编译与安装 ardupilot_gazebo 插件

`ardupilot_gazebo` 是 Gazebo 仿真 ArduPilot 必不可少的桥接插件。由于该插件编译时依赖工作空间内的自定义消息（如 `rsos_msgs`），因此必须**先初始化 ROS 环境环境变量后再编译**。

### 5.1 编译插件
```bash
# 1. 确保先让 CMake 能够检测到 ROS 环境
cd ~/catkin_ws
catkin build rsos_msgs
source devel/setup.bash

# 2. 进入 ardupilot_gazebo 目录进行编译
cd ~/catkin_ws/src/ardupilot_gazebo
mkdir -p build && cd build
cmake ..
make -j$(nproc)

# 3. 将插件强行注入至 Gazebo 默认的系统目录下
sudo make install
```

### 5.2 配置 Gazebo 模型与资源路径
为了使 Gazebo 能够识别 ArduPilot 仿真模型与世界文件，请向 `~/.bashrc` 追加以下配置：
```bash
echo 'source /usr/share/gazebo/setup.sh' >> ~/.bashrc
# 请将 ~/catkin_ws/src/ 替换为您实际的工作空间路径
echo 'export GAZEBO_MODEL_PATH=$HOME/catkin_ws/src/ardupilot_gazebo/models:$GAZEBO_MODEL_PATH' >> ~/.bashrc
echo 'export GAZEBO_RESOURCE_PATH=$HOME/catkin_ws/src/ardupilot_gazebo/worlds:$GAZEBO_RESOURCE_PATH' >> ~/.bashrc
source ~/.bashrc
```

## 6. 编译 Dankong 控制系统

根据实际使用场景，Dankong 支持以下两种编译运行模式：

### 模式 A：ROS 仿真/运行模式 (需要 ROS 环境)
用于运行完整的 Gazebo 多机仿真或通过 ROS 节点控制。
```bash
cd ~/catkin_ws

# 编译为 drone 模式 (支持参数: drone / dog / car)
catkin build -DROBOT=drone

# 加载环境变量
source devel/setup.bash
```

### 模式 B：无 ROS 独立部署模式 (无 ROS 依赖)
若仅需要 ArduPilot ＋ Dankong 无 ROS 独立版（脱离 ROS 1 底座），可直接调用部署打包脚本。
该脚本会自动调用 CMake 关闭 ROS 依赖、进行二进制静态链接打包，并在 `deploy_pkg` 目录中输出运行包。
> [!TIP]
> **推荐参数**：添加 `--add-bashrc` 参数，脚本会自动将打包生成的可执行目录路径追加到 `~/.bashrc` 的 `PATH` 环境变量中，让您在终端任意位置输入 `dankong` 即可启动。
```bash
cd ~/catkin_ws/src/dankong

# 执行打包部署脚本，并推荐带上 --add-bashrc
./sh/deploy.sh --robot drone --debug --add-bashrc
```
运行成功后，打包输出目录为 `dankong/deploy_pkg`。
* **独立运行方法**：
  * **若添加了 `--add-bashrc`**：刷新终端或执行 `source ~/.bashrc` 后，在任意路径执行：
    ```bash
    dankong
    ```
  * **未添加环境变量**：进入打包目录手动执行：
    ```bash
    cd ~/catkin_ws/src/dankong/deploy_pkg
    ./dankong
    ```

## 7. 启动仿真与自动化测试

运行 Gazebo 仿真需要完整的 ROS1 基础环境。启动后将自动载入指定的机器人模型、ArduPilot SITL 以及仿真节点。

运行以下 `rostest` 指令，可以在自动化环境中一键拉起仿真与测试验证：
```bash
# 确保在终端中 source 了工作空间
source ~/catkin_ws/devel/setup.bash

# 1. 运行无人机仿真测试
rostest dankong debug.test robot_type:=drone

# 2. 运行四足狗仿真测试
rostest dankong debug.test robot_type:=dog

# 3. 运行无人车仿真测试
rostest dankong debug.test robot_type:=car
```
